# 꺼내는 단어장 — 학생용 단어 암기·본문 순서 페이지 지침

이 프로젝트에서는 **완성된 자료를 받아서 학교별 학생 페이지로 만들어 올리는 일**만 한다. 자료는 두 종류다.

- **단어**: 단어장 엑셀. 단어를 고르고 뜻을 쓰는 일은 '클로드 단어장 생성' 프로젝트에서 끝난 상태로 넘어온다.
- **순서**: 교과서 본문·대화문의 문장 목록(교과서 순서). 순서시험(섞인 문장을 원래 순서대로 배열) 대비용이다. 2026-10-23에 추가.

## 1. 왜 이 페이지를 만들었나

- 학생들은 단어를 눈으로만 보거나(기시감만 생김) 깜지로 외운다(답을 보면서 써서 머리에서 꺼내는 횟수가 0번). 본문도 읽어서 '안다'고 느끼지만, 안 보고 순서대로 세워 보라면 못 세운다.
- 이 페이지는 **안 보고 떠올리기 → 바로 채점 → 틀린 것만 다시**를 하게 만든다.
- 다대일 수업이라 선생님이 학생 한 명 한 명 붙어 줄 수 없다. 그래서 순서·채점·다시 내기를 페이지가 대신하고, 단어 결과는 구글폼으로 모은다.
- 학생이 숙제로 혼자, 자기 폰으로 한다(친구와 같이 하는 활동이 아님).

- **저장소**: GitHub `kiarakimmy71617/vocab`. 공개 저장소이고, main 브랜치가 그대로 사이트가 된다(GitHub Pages: main / root).

## 3. 새 단어장이 왔을 때

### 먼저 물어볼 것 (이미 알고 있는 건 빼고)

1. 어느 학교·학년인가? 새 학교면 페이지 파일 이름도 정한다.
2. 그룹 이름(= 시험 이름)은 뭔가? 예: `2학기 기말 · 공통영어2 L3·4 · 247개`
3. **세트 크기와 묶음 크기**는? 학교마다 그때 정하니까 매번 확인한다.
   - 참고: 해송고 기말은 80·20, 시험 직전 복습이었던 어휘평가는 100·50.
4. 기존 그룹은 그대로 두는가, 시험이 끝난 그룹은 빼는가? 목록 순서는 시험이 가까운 그룹을 위로 한다.

### 작업 순서

1. **저장소 연결**: `add_repo(owner="kiarakimmy71617", repo="vocab", access="push")` 다음 `git clone --depth 1 https://github.com/kiarakimmy71617/vocab /home/claude/vocab`
2. **엑셀 가져오기**: `python3 _build/build.py import <엑셀> <데이터이름>`. 출력에 경고(번호 빠짐·중복, 같은 표제어)가 있으면 선생님께 알린다.
3. **학교 설정**: `_build/schools/<학교>.json`에 그룹을 추가한다. 새 학교면 아래 형식으로 파일을 새로 만든다.
4. **페이지 만들기**: `python3 _build/build.py <학교>`
5. **점검**: `node _build/check.js <페이지>.html`와 `python3 _build/smoke.py <페이지>.html`가 둘 다 통과해야 한다.
6. **올리기**: main에 commit → push. 1~2분 뒤 사이트에 반영된다.
7. **선생님께 알리기**: 학생 링크와 바뀐 점을 한두 줄로.

### 엑셀 형식 (build.py가 읽는 방식)

- 시트 이름이 `단어장`이면 그 시트를, 아니면 첫 시트를 읽는다.
- `영어`가 적힌 머리글 행 다음 줄부터 읽는다.
- 칸은 머리글 이름으로 찾는다. `영어`와 `단어 뜻`(또는 `뜻`)은 꼭 있어야 하고, `번호`, `참고`(또는 `본문 풀이`), `지문`(또는 `출처`·`구분`)은 있으면 쓴다.
- 지문 구분은 `지문` 칸으로 읽는다. 예전 방식처럼 A열에만 `[교재 | Lesson 3 | 제목]`이 적힌 구분 행이 있어도 읽는다.
  - `지문` 칸이 `16강 01`처럼 적혀 있으면 세트 카드에 `16강 01번 44 + 16강 02번 36`(지문별 단어 수)으로 표시된다.
- `▶`로 시작하는 회차 행은 무시한다. 세트는 아래 규칙대로 새로 나눈다.

### 학교 설정 형식

```json
{
 "page": "haesong.html",
 "short": "해송고1",
 "school": "해송고 1학년",
 "fields": [["학교", "해송고 1학년"]],
 "groups": [
  {"data": "haesong1-2026-2f", "group": "2학기 기말 · 공통영어2 L3·4 · 247개", "title": "기말",
   "id_prefix": "haesong1-2026-2f", "set_size": 80, "batch": 20, "active": true}
 ]
}
```

- `page`: 학생 링크의 파일 이름. 새로 만들 때는 학교 영문 이름 + 학년으로 한다(예: `songdo1.html`). `haesong.html`은 이미 링크가 나가서 그대로 둔다.
- `short`: 브라우저 탭 제목. `school`: 제출 폼의 '학교' 칸에 들어가는 값. `fields`: 페이지 맨 위에 표시되는 칸.
- `groups`: 적힌 순서가 그대로 페이지 목록 순서다. 단어 그룹과 순서 그룹(`"type": "order"`, 아래 참고)을 섞어 넣을 수 있다.
  - `note`를 적으면 세트 카드 설명이 그 글로 고정된다. 안 적으면 지문 구성이 자동으로 표시된다.
  - 시험이 끝난 그룹은 지우지 말고 `"active": false`와 `memo`를 남긴다. 그래야 다시 켤 수 있다.
- `id_prefix`: `<학교영문><학년>-<연도>-<시험코드>` 형식으로 쓴다(`2f` = 2학기 기말, `voc2` = 어휘평가 2차, `order` = 순서시험).

## 3-1. 새 순서 연습(본문·대화문)이 왔을 때

### 먼저 물어볼 것

1. 어느 학교·학년, 어느 페이지인가? (중3 동아는 `donga3.html`)
2. 어느 과까지? 세트 하나 = 과 하나다(대화문 + 본문 전부).
3. **정답 순서가 담긴 자료**: 교과서 순서대로 적힌 본문·대화문(영작 테스트 정답 부분 등)이나 순서시험 답지. 섞인 시험지만으로는 만들지 않는다(순서를 추측하게 됨).
4. 지문을 어떻게 나눌지는 **순서시험지의 지문 단위를 그대로** 따른다. 교과서 본문 단락과 다를 수 있다(예: 동아 7과 본문 1은 교과서 본문 1+2를 합친 12문장). 이름도 시험지 이름을 쓰고, 교과서 소제목이 있으면 `본문 2 · Enjoy Your Meal`처럼 덧붙인다.

### 작업 순서

1. 저장소 연결·clone (위와 같음).
2. **텍스트 만들기**: `_build/src/<데이터이름>.txt`에 아래 형식으로 쓴다. 말한 사람 표시(B:, G:, Linda: 등)는 빼고 문장만 쓴다(시험지에도 없음). 자료가 PDF면 `pdftotext -layout`으로 뽑아서 답지와 대조해 둔다.
3. **가져오기**: `python3 _build/build.py import-order _build/src/<데이터이름>.txt <데이터이름>`. 경고(문장 2개 미만, 똑같은 문장 두 번, 말한 사람 표시 남음)가 있으면 고친다.
4. **학교 설정**에 순서 그룹을 넣는다 → 빌드 → `check.js`·`smoke.py` → push → 선생님께 링크.

### 순서 텍스트 형식

```
# L5 | 5과 · From Trash to Music        ← 과 = 세트 하나. '|' 앞은 세트 ID에 들어가는 키(영문·숫자), 뒤는 세트 제목
## Listen & Speak 1 ① | 대화문          ← 지문. '|' 앞은 지문 이름, 뒤는 종류(대화문/본문)
Hey, Bora. Welcome to our rock band.     ← 문장 한 줄에 하나, 교과서 순서대로
Thanks. I’m looking forward to playing in a concert with you.
...
## 본문 1 | 본문
...
```

### 순서 그룹 설정

```json
{"type": "order", "data": "donga3-2026-order", "group": "순서시험 대비 · 동아 5·6·7과 (대화문 + 본문)",
 "id_prefix": "donga3-2026-order", "active": true}
```

- 세트 ID는 `id_prefix-과키`(예: `donga3-2026-order-L5`)다. **과 키나 id_prefix를 바꾸면 그 과의 진행 기록이 사라진다.**
- `lessons`: `["L5", "L6"]`처럼 적으면 그 과만 넣는다. 안 적으면 데이터의 모든 과.
- 시험이 끝난 과를 빼려면 `lessons`에서 빼거나, 데이터는 두고 그룹을 `"active": false`로 한다. 텍스트에서 문장을 지우진 않는다.

## 4. 정해진 규칙

### 세트와 묶음 (단어)

- **세트**는 숙제 한 번 분량이다. 번호순으로 `set_size`개씩 자르고, 마지막 자투리가 세트 크기의 절반보다 적으면 앞 세트에 합친다(247개를 80개씩 → 80·80·87).
- **묶음**은 한 번에 거르고 외우는 단위다. 지문 경계와 상관없이 `batch`개 이하로 고르게 나눈다(80개 → 20×4, 87개 → 18·18·17·17·17).
- **세트 ID(`id_prefix-첫번호-끝번호`)는 학생 진행 기록을 찾는 열쇠다.**
  - 학생에게 링크가 나간 뒤 `id_prefix`나 `set_size`를 바꾸면, 그 그룹의 진행 기록이 사라진다. 꼭 바꿔야 하면 선생님께 먼저 말한다.
  - `batch`만 바꾸면, 이미 시작한 학생은 원래 묶음으로 끝까지 하고 새로 시작하는 세트부터 바뀐다.
- 같은 학교·학년의 단어장이 여러 개면 한 페이지에 그룹으로 넣는다(해송고: 기말 + 어휘평가).

### 학습 흐름 (단어 · 페이지가 알아서 진행함)

- **외우기**: 묶음마다 ①→② 순서로 하고, 모든 묶음이 끝나면 ③으로 간다.
  1. **거르기**: 영→한. 소리 내서 뜻을 말한 다음 뜻을 열고, 알았어/애매해/몰랐어로 스스로 채점한다. 5초 넘게 걸리면 애매로 누르라고 안내가 뜬다.
  2. **집중**: 모른 단어는 3~6장 뒤에 다시 나온다. 한→영은 철자를 직접 쳐서 자동으로 채점한다. 다 맞혀야 그 묶음이 끝난다.
  3. **마지막 점검**: 세트 전체를 섞어서 한 번씩 본다(영→한·한→영이 섞여 나옴). 틀리면 다시 나온다. 끝나면 결과 화면과 제출 칸이 나온다.
- **빠른 점검**: ③만 한다.
- **끈질긴 단어**: 두 번 이상 틀렸거나 마지막 점검에서 틀린 단어만 다시 한다.
- 진행 상황은 폰에 저장돼서, 중간에 나갔다가 와도 이어서 할 수 있다.

### 채점 기준 (단어)

- **영→한**: 「단어 뜻」 칸만 떠올리면 '알았어'다. 「참고」 칸(본문 풀이, 다른 빈출 뜻)은 뜻을 열었을 때 작게 보여주는 확인용이다. ` / `와 ` — ` 기준으로 줄을 나눠 보여준다.
- **한→영**: 철자까지 맞아야 정답이고, 대소문자는 안 본다.
  - 자리표시(A·B·V·~·…·sb·sth·one's·+, 한글 '주어'·'형용사' 등)는 비워도 되고 아무 말이나 넣어도 정답이다.
  - 괄호 부분((to), (un))은 넣어도 빼도 정답이다. `a/b`는 둘 다 정답이다.
  - 뜻 칸이 완전히 같은 단어끼리(prior·former = 이전의)는 어느 쪽을 써도 정답이다.
  - 문제 화면에서는 답을 알려주는 영어 괄호를 숨긴다("자극 (pl. stimuli)" → "자극"). (v.) 같은 품사 표시는 남긴다.
  - 표제어가 8단어 이상이면 한→영 철자 문제에서 빠진다.

### 순서 맞추기 (순서 세트)

- **세트 = 과 하나**, 그 안의 **지문**(대화문·본문)을 시험지 순서대로 하나씩 낸다. 지문마다 문장을 **매번 새로 섞는다**(교과서 순서 그대로 나오는 일은 없음). 그래서 자리나 기호를 외워도 소용없다.
- 학생은 안 보고 **첫 문장부터 순서대로 탭**한다. 탭한 문장의 동그라미에 번호가 찍힌다. 이미 놓은 문장을 다시 탭하면 **거기부터 다시 놓는다**(그 번호 이후가 지워짐). '처음부터 다시 놓기'도 있다. 다 놓아야 '확인'이 켜진다.
- **채점**: 교과서 순서와 완전히 같아야 정답이다. 말한 사람 표시가 없어서 말이 되는 다른 배열(답지의 ※ 표시)도 오답으로 본다 — 시험지가 "원래 순서대로"를 요구하고, 외운 그대로 세우는 게 목적이라서. 선생님이 다른 배열도 인정하기로 하면 그때 바꾼다.
- 확인 뒤에는 **교과서 순서로 다시 나열**하고, 자리를 틀린 문장을 빨갛게 표시하며 '내 답 n번째'를 단다. 틀린 지문은 큐 맨 뒤로 가서 다시 나오고(마지막 지문이면 바로 다시, 새로 섞여서), **세트의 모든 지문을 맞혀야 끝**난다.
- **결과 화면**: 걸린 시간, 한 번에 맞힌 지문 수, 다시 한 지문 목록(몇 번 만에 맞혔는지). **'틀린 지문만'** 버튼으로 그 지문들만 다시 할 수 있다. 제출 칸은 없다.
- 세트 카드: `9지문 · 78문장`, 지문 구성(`대화문 5 + 본문 4`), 진행 중(맞힌 지문 n/N)·지난 기록(한 번에 n/N). 버튼은 '순서 맞추기'(진행 중이면 '이어서 하기'·'처음부터')와 '틀린 지문만 n'.
- 진행 기록은 단어와 같은 방식으로 폰에 저장된다(섞인 순서와 놓은 번호까지 복원됨).

### 제출 (단어 세트만)

- '외우기'를 끝까지 했을 때만 결과 화면에 제출 칸이 나온다. 빠른 점검이나 끈질긴 단어 모드로는 제출할 수 없다. 순서 세트에는 제출이 없다(선생님이 필요 없다고 함).
- 학생이 이름을 쓰고 '제출하러 가기'를 누르면, 구글폼이 이름·학교·세트·걸린 시간·끈질긴 단어가 채워진 채로 열린다. 세트는 `기말 · 1~80번 · 외우기`, 끈질긴 단어는 `개수: 목록` 형식이다. 학생은 Submit만 누르면 된다.
- 이름은 폰에 기억돼서 다음부터는 자동으로 채워진다. 학생이 숫자를 고쳐서 낼 수 있으니, 수업 단어시험과 같이 본다.
- **폼 연결값**(build.py의 `FORM`):
  - 주소: `https://docs.google.com/forms/d/e/1FAIpQLSfsvGXKVGASob6ylSlyCFKyEahrzGSqFNtwlaYEvA1AHOanww/viewform`
  - 이름 `entry.2087311015` · 학교 `entry.331616395` · 세트 `entry.1245213658` · 걸린 시간 `entry.1880995760` · 끈질긴 단어 `entry.770504430`
- **폼 설정 조건**: 이메일 수집 안 함, 응답 1회 제한 끔, 게시(Publish)된 상태. 앞의 두 개가 켜져 있으면 학생에게 구글 로그인을 요구하고, 게시 전이면 "not published"가 뜬다. 폼 질문을 바꾸면 Pre-fill form 링크를 다시 받아 entry 번호를 고친다.

### 발음 (단어)

- 폰에 들어 있는 영어 음성으로 읽는다. 버튼이 나오는 곳은 세 군데다.
  - 영→한 카드: '발음' 버튼
  - 한→영 카드: 답을 확인한 뒤에만(답 쓰기 전에 들으면 정답을 알려주는 셈이라)
  - 결과 화면: 끈질긴 단어 옆
- 카톡 같은 앱 안 브라우저(특히 안드로이드)에서는 음성 기능이 없어서 버튼이 안 보인다. 그래서 **크롬이나 사파리로 열라고 안내**한다.
- 진행 기록은 연 브라우저에만 저장된다. **매번 같은 브라우저로 열라고** 안내한다(페이지 맨 아래에도 적혀 있음).

### 페이지 표시

- 학교 페이지에서는 '단어 직접 넣기'를 숨긴다(build.py가 항상 `paste: false`로 만든다). 맨 위 표시 칸에는 학교 이름이 나온다.
- 페이지에 있는 세트 종류에 따라 제목·안내 상자가 바뀐다: 단어만 → '꺼내는 단어장' + 외우는 방법, 순서만 → '본문 순서 맞추기' + 순서 맞추는 방법(탭 제목도 같이), 둘 다 → '꺼내는 단어장' + 안내 상자 둘 다.
- 저장소 맨 위의 `index.html`은 예시 단어·예시 순서 세트와 '단어 직접 넣기'가 있는 선생님 확인용 데모다(`python3 _build/build.py demo`로 다시 만듦). 학생용이 아니다.

## 6. 페이지 자체를 고칠 때

- 문구나 동작은 `_build/template.html`에서만 고친다. 그다음 모든 학교 페이지와 데모(`build.py demo`)를 다시 만들고, 점검한 뒤 올린다. 학교 html 파일은 직접 고치지 않는다(다음 빌드 때 덮어써짐).
- 정답 인식 로직(matchItem 등)과 순서 모드의 핵심(prepareOrder·shuffleOrder·gradeOrder)은 `/*PURE-START*/ ~ /*PURE-END*/` 사이에 있어야 check.js가 시험할 수 있다.
- 고친 뒤에는 `check.js`와 `smoke.py`가 **모든 페이지**에서 통과해야 올린다. 화면을 바꿨으면 smoke.py에 캡처 경로를 줘서 화면을 직접 확인한다(순서 세트는 놓는 중·정답·오답 화면이 따로 찍힘).
- 규칙이 바뀌면 이 지침을 두 곳 다 고친다: 프로젝트 'github 단어연습'의 `claude/꺼내는단어장_지침.md`(Projects 도구 `project_write`로 덮어쓰기)와 저장소의 `_build/지침.md`. 선생님께 따로 부탁할 필요 없다.
